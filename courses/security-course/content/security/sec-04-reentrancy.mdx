## The pattern you are hunting

Every reentrancy bug is the same three lines in the wrong order:

```solidity
function withdraw() external {
    uint256 bal = s_balances[msg.sender];
    (bool ok, ) = msg.sender.call{value: bal}(""); // 1. give value away
    require(ok);                                    // 2. hope
    s_balances[msg.sender] = 0;                     // 3. bookkeeping, too late
}
```

The call at line 1 hands control to arbitrary code while the contract still
believes `msg.sender` has `bal`. Their `receive()` fires, calls `withdraw()`
again, and the loop repeats until the vault is empty or gas runs out. That is
exactly how ~$60M left The DAO in 2016: a recursive call inside a split.

<SpotIt>

In an unknown codebase, grep for the shape of the bug, not the name:

```bash
grep -rn "\.call{" src/
grep -rn "\.transfer(\|\.send(" src/
grep -rn "msg.sender.call" src/
```

Read every hit and answer one question: does any state change AFTER this line
depend on values the callee could influence? If yes, rank it as a reentrancy
candidate, then check whether the same state is reachable from a sibling
function (cross-function) or from a view called by a price reader
(read-only).

</SpotIt>

<FixIt>

Two independent fixes, both standard:

```solidity
// 1. Checks-Effects-Interactions: state first, call last
s_balances[msg.sender] = 0;
(bool ok, ) = msg.sender.call{value: bal}("");
require(ok);

// 2. Mutex as belt and braces
modifier nonReentrant() {
    require(s_locked == false, "reentrancy");
    s_locked = true;
    _;
    s_locked = false;
}
```

Re-run the exploit test: it must now revert at the call, and the honest
withdraw test must stay green.

</FixIt>

## Real-world case: The DAO, June 2016

The DAO held ~$60M of ETH. Its split() function sent ETH before finalizing
internal accounting, and the attacker re-entered split recursively in one
transaction, draining funds into a child DAO. The Ethereum Foundation's
emergency writeup describes the recursive calling vulnerability and the
proposed soft fork in plain terms.

Read it: https://blog.ethereum.org/2016/06/17/critical-update-re-dao-vulnerability

Background and aftermath (including the hard fork): https://en.wikipedia.org/wiki/The_DAO
