## Everything public, nothing random

The EVM has no entropy source. Every value a contract can read on-chain was
either published by the protocol (block attributes), submitted by a caller
(msg.sender, calldata), or stored earlier. A "random" winner drawn from any
combination of those is a computation anyone can replay. In 2018 whole rounds
of a popular ETH game were consistently captured by contracts that predicted
the outcome and only played when profitable.

The three usual culprits:

```solidity
uint256 seed = uint256(
    keccak256(abi.encodePacked(block.timestamp, blockhash(block.number - 1), msg.sender))
);
uint256 winner = participants[seed % participants.length];
```

Every term is public the moment the transaction is in the mempool. The
attacker computes `seed` for their own transaction, and if they lose, they
replace it with a higher-fee version or simply do not send it.

<SpotIt>

```bash
grep -rn "block.timestamp\|blockhash\|block.difficulty\|prevrandao" src/
grep -rn "keccak256(abi.encodePacked" src/
```

Any keccak256 over block attributes plus user input is a candidate. Ask:
could a miner or a caller move any input? Could they see the result before
committing funds? If either answer is yes, the randomness is exploitable.

</SpotIt>

<FixIt>

Two production fixes, pick by stake size:

1. **Commit-reveal**: participants commit `keccak256(secret)` first; the
   winner is drawn later from the revealed secrets plus a future block hash
   nobody controls at commit time.
2. **Verifiable randomness**: request the draw from a VRF oracle (Chainlink
   VRF on mainnet) and verify the proof on-chain before paying out.

Re-run your prediction test: with either fix, the attacker's "compute before
committing" trick must no longer reveal the winner early.

</FixIt>

## Real-world case: documented weakness, real money

The Smart Contract Weakness Classification files this as SWC-120, with live
sample contracts including one deployed on Ethereum that seeds from
block.timestamp and blockhash. Gambling DApps on multiple chains lost pots to
predicted or grinded draws throughout 2017-2019; the pattern is the same
everywhere: public seed, predictable winner.

Read the classification and its samples: https://swcregistry.io/docs/SWC-120

Sigma Prime's survey of the same class, with more examples: https://blog.sigmaprime.io/solidity-security.html
